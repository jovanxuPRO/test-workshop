## 1. 业务背景
E-Commerce 订单系统是企业内部使用的订单管理平台。运营人员通过该平台创建订单、跟踪订单状态、管理订单流转。与传统电商不同，本系统侧重企业内部订单管理，不涉及在线支付对接（支付操作由运营人员手动确认）。

## 2. 核心流程
```
创建订单 → 确认订单 → 确认支付 → 发货 → 完成
              ↘ 取消        ↘ 取消
```

## 3. 功能需求

### 3.1 创建订单
- 运营人员选择商品及数量，系统**自动计算**订单总金额
- **金额计算规则**：总金额 = Σ(单品单价 × 数量)，精确到分
- 创建订单时**自动扣减库存**（预占），防止超卖
- 订单初始状态为 `created`
- 订单号格式：`o` + 12位字母数字（不可预测）

### 3.2 订单流转
- 每个状态仅允许转换到指定状态：

| 当前状态 | 可转换到 |
|----------|----------|
| created | confirmed, cancelled |
| confirmed | paid, cancelled |
| paid | shipped |
| shipped | delivered |
| delivered | （终态） |
| cancelled | （终态） |

- **禁止跳级**：不能从 created 直接变成 shipped
- **禁止回退**：不能从 delivered 变回 paid

### 3.3 取消订单
- 仅 `created` 和 `confirmed` 状态可取消
- 已支付（`paid`）及之后状态的订单**不可取消，应走退款流程**
- 取消后**恢复已扣减的库存**
- 取消后订单状态变为 `cancelled`

### 3.4 订单列表
- 支持按状态筛选（下拉单选）
- 支持分页（默认每页 20 条）
- 管理员可查看所有订单，普通用户仅可查看自己的订单

## 4. 业务规则

| 编号 | 规则 | 严重级别 |
|------|------|----------|
| R001 | 订单金额 = 所有商品单价×数量之和，精确到 0.01 | 严重 |
| R002 | 创建订单时商品库存必须 ≥ 订购数量，否则拒绝并提示"库存不足" | 严重 |
| R003 | 订单金额必须 > 0 | 严重 |
| R004 | 订单至少包含 1 件商品 | 严重 |
| R005 | 状态流转必须遵循上述状态机，违反则返回错误 | 严重 |
| R006 | 取消订单必须恢复库存 | 严重 |
| R007 | `paid` 及之后状态不可取消 | 重要 |
| R008 | 同一商品可被多个订单同时扣减库存（并发控制） | 重要 |
| R009 | 订单号不可重复 | 严重 |

## 5. 边界与异常场景

### 5.1 并发下单
- 场景：A 和 B 同时创建包含同一商品的订单，该商品库存仅剩 1 件
- **预期**：只有第一个请求成功，第二个返回"库存不足"
- **风险**：无并发控制会导致超卖（库存变负数）

### 5.2 超大订单
- 场景：单个订单包含 999 件商品
- 预期：正常处理，但系统应验证每个商品的库存

### 5.3 空订单
- 场景：提交 items 为空数组 `[]`
- 预期：返回 400 错误，提示"items is required"

### 5.4 商品不存在
- 场景：订单包含已删除的商品 ID
- 预期：返回 404，提示"商品 {id} 不存在"

### 5.5 重复提交
- 场景：网络抖动导致同一订单被提交两次
- 预期：不应创建重复订单（幂等性要求——**v1.2 未实现，待后续版本**）

## 6. 非功能性需求
- 创建订单接口响应时间 < 500ms（P95）
- 支持并发 50 QPS 不出现库存超卖
- 订单查询支持分页，单页最多返回 100 条
