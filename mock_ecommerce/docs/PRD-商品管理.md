## 1. 业务背景
商品管理是 E-Commerce 系统的基础数据模块。管理员负责维护商品信息（名称、价格、库存、分类），商品数据被订单模块引用。

## 2. 功能需求

### 2.1 商品 CRUD
- **创建**：管理员填写名称、价格、库存、分类
- **查询**：支持按分类筛选、按名称模糊搜索、分页
- **更新**：可修改名称、价格、库存、分类中的任意字段（部分更新）
- **删除**：删除商品后，已有订单仍可查看该商品信息（不影响历史数据）

### 2.2 库存管理
- 库存由订单模块自动扣减和恢复
- 商品管理模块提供库存查询，不直接修改库存（修改接口保留但需管理员权限）
- **低库存预警**：库存 < 20 件时在 Dashboard 显示

### 2.3 价格管理
- 价格单位为人民币元，精确到 0.01
- 价格变更**不影响已创建订单**（订单锁定下单时的价格）
- ⚠ **争议需求（v2.1 待确认）**：价格变更为 0 是否允许？运营说允许（赠品场景），风控说禁止（防止误操作）

## 3. 业务规则

| 编号 | 规则 | 严重级别 |
|------|------|----------|
| R101 | 商品名称必填，长度 1-100 字符 | 严重 |
| R102 | 价格必须 > 0（整数或小数，最多 2 位） | 严重 |
| R103 | 库存必须 ≥ 0 | 严重 |
| R104 | 商品 ID 系统自动生成，不可手动指定 | 一般 |
| R105 | 删除商品不检查是否有关联订单 | 一般 |
| R106 | 同一名称+分类组合可以存在多个（无唯一约束） | — |

## 4. 边界与异常场景

### 4.1 超大价格
- 场景：价格设为 99999999.99
- 预期：允许（系统不做上限限制）

### 4.2 负库存
- 场景：通过更新接口将库存设为 -1
- 预期：返回 400，提示"stock must be >= 0"

### 4.3 删除有订单的商品
- 场景：商品 p001 已被多个订单引用，管理员删除它
- 预期：删除成功，已有订单仍可查看（不级联删除）
- ⚠ **潜在问题**：订单详情中关联的商品 ID 将无法解析为有效商品名

### 4.4 商品名为空
- 场景：name = "" 或 name = "   "（纯空格）
- ⚠ **文档未明确**：是否应拒绝纯空格名称？建议做 trim 处理。

## 5. 与其他模块的交互
- 订单模块读取商品：创建订单时查询商品价格和库存（实时读取）
- 库存扣减：由订单模块直接修改 `stock` 字段（非通过商品模块 API）
- 价格锁定：订单创建时记录 `unit_price`（订单表独立字段，不依赖商品表当前价格）
