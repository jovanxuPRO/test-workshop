# PRD-003：退款管理模块

## 版本历史
| 版本 | 日期 | 作者 | 变更说明 |
|------|------|------|----------|
| v1.0 | 2026-01-15 | 产品部 | 初稿 |

## 1. 业务背景
退款是订单售后流程的核心环节。客户（内部使用者）对已支付的订单发起退款申请，管理员审批后执行退款。退款审批通过后**自动取消关联订单**并**恢复库存**。

## 2. 核心流程
```
已支付订单 → 申请退款 → 管理员审批 → 通过（取消订单+恢复库存）
                                    → 驳回（订单保持原状态）
```

## 3. 功能需求

### 3.1 申请退款
- 仅 `paid`、`shipped`、`delivered` 状态的订单可申请退款
- `created` 和 `confirmed` 订单应走取消流程，不可申请退款
- 退款金额必须 > 0
- 退款金额 ≤ 订单总额（防止超额退款）
- 金额留空时**默认全额退款**
- 退款单状态初始为 `pending`

### 3.2 审批退款
- 仅管理员可审批
- **通过**：退款单状态 → `approved`，关联订单状态 → `cancelled`，恢复订单中所有商品的库存
- **驳回**：退款单状态 → `rejected`，订单状态**保持不变**
- 已审批的退款单不可再次审批

### 3.3 退款查询
- 管理员可查看所有退款单
- 普通用户仅可查看自己订单的退款单

## 4. 业务规则

| 编号 | 规则 | 严重级别 |
|------|------|----------|
| R201 | 仅 paid/shipped/delivered 状态可申请退款 | 严重 |
| R202 | 退款金额 > 0 且 ≤ 订单总额 | 严重 |
| R203 | 审批通过后必须恢复库存 | 严重 |
| R204 | 驳回后订单状态不变 | 严重 |
| R205 | 同一订单可多次申请退款（上一单被驳回后） | 一般 |
| R206 | ⚠ **争议**：已退款的订单能否再次申请退款？PRD 未明确 | 待确认 |
| R207 | ⚠ **争议**：delivered 订单退款通过后，已发货的商品库存恢复是否合理？ | 待确认 |

## 5. 边界与异常场景

### 5.1 超额退款
- 场景：订单总额 2999，申请退款 5000
- 预期：返回 400，提示"退款金额超过订单总额"

### 5.2 退款金额为 0
- 场景：amount = 0
- 预期：返回 400，提示"退款金额必须 > 0"

### 5.3 重复审批
- 场景：退款单已通过，再次点击通过
- 预期：返回 400，提示"退款已 approved"

### 5.4 订单不存在时申请退款
- 场景：order_id = "nonexistent"
- 预期：返回 404，提示"订单不存在"

### 5.5 已取消订单申请退款
- 场景：订单状态为 cancelled
- 预期：返回 400，提示"订单状态不允许退款"

### 5.6 全额退款后库存恢复
- 场景：订单包含 p001×2，退款批准通过
- 预期：p001 库存 +2，订单状态 → cancelled

## 6. PRD 之间的冲突标注

| 冲突点 | PRD-001（订单） | PRD-003（退款） | 建议 |
|--------|----------------|----------------|------|
| cancelled 状态 | 取消 = 订单关闭 | 退款通过 = 取消订单 | 退款通过后订单变为 cancelled，归类为"已取消"可能有歧义——是用户取消还是退款取消？建议增加 `refunded` 状态 |

## 附录：跨 PRD 测试矩阵

测试人员应交叉阅读三份 PRD，关注以下交互点：

| 交互 | 涉及模块 | 关键测试点 |
|------|----------|------------|
| 下单→扣库存 | 订单+商品 | 扣减精度、并发安全、库存为0时的行为 |
| 取消→恢复库存 | 订单+商品 | 恢复数量是否正确、取消后能否再次下单同一商品 |
| 退款→恢复库存 | 退款+订单+商品 | 退款通过后库存+订单状态联动 |
| 价格变更→已有订单 | 商品+订单 | 价格变更后已有订单金额不变 |
| 删除商品→已有订单 | 商品+订单 | 删除后订单详情中商品 ID 悬空 |
| 退款驳回→再申请 | 退款+订单 | 同一订单多次驳回/申请是否正确处理 |
